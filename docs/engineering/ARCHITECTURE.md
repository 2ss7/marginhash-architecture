# Как устроен MarginHash

MarginHash объединяет каталог asic, историю цен и расчётные показатели в одном веб-сервисе. Сбор предложений и подготовка данных работают отдельно от показа страниц. Пользователь открывает готовый каталог без ожидания обхода магазинов и пересчёта всех моделей.

## Путь от магазина до страницы

~~~text
сайты продавцов → сбор предложений → нормализация моделей → sqlite
                                              ↓
                                    подготовленные данные
                                              ↓
                                    веб-приложение → браузер
~~~

Планировщик обновляет предложения, историю цен и подготовленные данные каталога. Веб-приложение на Flask читает опубликованные результаты. Команды ручного обновления передаются планировщику через отдельную файловую границу. Обычный HTTP-запрос не запускает парсер напрямую.

## Хранение и обновление

В sqlite хранятся нормализованные модели и предложения asic. История цен тоже использует sqlite. Позиции связаны с точками изменения или удержания цены. Это сокращает объём повторяющихся записей. Для истории старый JSON служит источником явного импорта. У части читателей каталога ещё есть JSON fallback. Переход хранения на sqlite пока не завершён для всего проекта.

Cache отдельных магазинов, сетевые ставки и подготовленные данные разнесены по runtime-директориям. Данные для API публикуются атомарной заменой файла. По версии данных веб-процессы обновляют свой cache без пересборки каталога при каждом запросе.
